# 인스타그램으로 계속하기 (Instagram Login / Meta) 연동 완벽 가이드

> Studio Canvas AI (Next.js) — **「Instagram으로 계속하기」** UI 및 Meta 인증 파이프라인  
> 기준 코드: `AuthModal` Instagram 버튼 → `signInWithInstagram` ≡ `signInWithFacebook` → Supabase `provider: "facebook"`  
> 최종 정리일: 2026-08-08  
> 파일: `Integration_Log_v6.txt` (프로젝트 Root)

---

## 0. 한 줄 요약 — 가장 중요한 사실

| 항목 | Studio Canvas 실제 구현 |
|------|-------------------------|
| UI 라벨 | 「Instagram으로 계속하기」 / Continue with Instagram |
| 실제 OAuth provider | **`facebook`** (Supabase built-in Facebook Login) |
| Instagram 전용 API | **사이트 로그인에 사용하지 않음** (Basic Display / Instagram Graph Business API 미호출) |
| Alias | `signInWithInstagram = signInWithFacebook` |
| Meta Redirect URI | `https://oorujqbivznftsyqilyj.supabase.co/auth/v1/callback` |
| App ID | `1527934262363418` (Facebook 앱과 **동일**) |
| `custom:instagram` | **구성·사용하지 않음** |
| Graph 호출 주체 | Supabase GoTrue ↔ Meta (앱 Next.js Route 없음) |
| 이메일 | 미제공 시 `{id}@users.facebook.id` (Facebook 경로와 동일) |

이 제품의 「인스타그램 로그인」은 **별도 Instagram OAuth 앱이 아니라, Meta Facebook Login을 Instagram 브랜드 UI로 노출한 통합 로그인**입니다.  
Instagram Graph API(비즈니스/크리에이터 미디어·인사이트)와 혼동하면 Redirect·스코프·계정 유형에서 잘못된 설정을 하게 됩니다.

관련: 페이스북 상세는 `Integration_Log_v5.txt`.

## 1. 핵심 파일 구조 및 라우팅

### 1.1 프론트엔드 트리거 · 인증 요청 진입점

| 경로 | 역할 |
|------|------|
| `components/AuthModal.tsx` | Instagram 버튼, `InstagramLogo`, `id === "instagram"` → `handleMetaLogin()` |
| `lib/supabase/oauth.ts` | `TO_SUPABASE.instagram = "facebook"`, **`signInWithInstagram`**, `signInWithFacebook` |
| `lib/i18n/locales/kr.ts` 등 | `continueWithInstagram` |
| `components/CreditsProvider.tsx` | UI provider 타입 `"instagram"` |
| `lib/db/types.ts` | `AuthProviderId`에 `"instagram"` (매핑/표시용; 실제 IdP는 facebook인 경우 다수) |
| `lib/social.ts` / `FooterClient.tsx` | **마케팅용** Instagram 프로필 링크 — **로그인 OAuth와 무관** |

**버튼 클릭 경로:**

```
AuthModal SOCIAL order … → instagram
  onClick → handleMetaLogin()   // facebook과 동일 핸들러
    → signInWithFacebook(next)  // signInWithInstagram는 동일 함수
      → supabase.auth.signInWithOAuth({
           provider: "facebook",   // ← Instagram UI여도 facebook
           options: { redirectTo: `${origin}/auth/callback?next=…` },
           // scopes 미지정 (email Invalid Scopes 방지)
         })
```

UI만 Instagram 그라데이션/아이콘이고, 네트워크·IdP는 Facebook Login입니다.

### 1.2 콜백 · 토큰 · (Instagram) Graph 관련 라우트

| 경로 | 역할 |
|------|------|
| Meta Valid OAuth Redirect URI | `https://oorujqbivznftsyqilyj.supabase.co/auth/v1/callback` |
| Supabase GoTrue | code → Meta access_token → **Facebook Graph `/me`(등)** → `auth.users` |
| `middleware.ts` | `/` + `code`/`error` → `/auth/callback` |
| `app/auth/callback/route.ts` | PKCE exchange → `/auth/bridge` |
| `lib/supabase/exchange.ts` | 세션 쿠키 기록 |
| `app/auth/bridge/*` | 모바일/Meta 쿠키 지연 재시도 → supabase-bridge |
| `app/api/auth/supabase-bridge/route.ts` | NextAuth JWT + 앱 유저 |
| `lib/auth.ts` | Auth.js `Instagram` provider — **폴백 전용**, 주 경로 미사용 |

**앱에 Instagram Graph 전용 API Route는 없습니다.**  
(예: `/api/auth/instagram/userinfo` 없음. 네이버 userinfo 프록시와 다름.)

### 1.3 Token Exchange / API 호출 로직 구조

```
[Browser] Instagram 버튼
    → signInWithOAuth(provider: "facebook")
         │
         ▼
[Meta] Facebook Login dialog
    (사용자는 IG에 연결된 FB 계정 / Meta 계정으로 동의 가능)
         │  redirect_uri = Supabase /auth/v1/callback
         ▼
[Supabase GoTrue]
    1) state / PKCE
    2) Meta token endpoint (Authorization Code → access_token)
    3) Graph 사용자 조회 (Facebook Login 경로; 앱이 IG Graph Business API 미사용)
    4) auth.users
    5) 앱 redirectTo 로 PKCE code
         ▼
[App] /auth/callback → exchangeCodeForSession
         ▼
[App] /auth/bridge → POST /api/auth/supabase-bridge
         ▼
[App] extractSupabaseOAuthProfile (facebook identity + synthetic email)
```

#### 「Instagram Graph API」와의 관계 (혼동 방지)

| API / 제품 | 용도 | 이 앱 로그인에 사용? |
|------------|------|----------------------|
| **Facebook Login** + Graph `/me` | 웹 소셜 로그인 | **예 (GoTrue)** |
| Instagram Basic Display | 개인 IG 미디어 (레거시/제한) | **아니오** |
| Instagram Graph API (Business/Creator) | 페이지 연동 비즈니스 계정, 인사이트, 게시 | **아니오** |
| Supabase `custom:instagram` | 커스텀 OIDC | **아니오 (의도적 미사용)** |

사이트 「계속하기」는 **신원(identity) 확보**가 목적이고, IG 피드/미디어 권한이 목적이 아닙니다.

### 1.4 엔드투엔드

```
User taps Instagram CTA
  → Meta (Facebook Login)
  → Supabase session
  → /auth/callback → /auth/bridge
  → app session (± terms-consent)
```

## 2. 트러블슈팅 및 에러 핸들링

### 2.1 Redirect URI 불일치

#### 증상
- Meta “URL Blocked”, redirect_uri mismatch  
- Instagram 버튼만 실패처럼 보이지만 Facebook 버튼도 동일 원인

#### 해결

| 위치 | 올바른 값 |
|------|-----------|
| Meta Valid OAuth Redirect URIs | `https://oorujqbivznftsyqilyj.supabase.co/auth/v1/callback` |
| 앱 `redirectTo` | `https://www.studio-canvas-ai.com/auth/callback?next=…` |
| Supabase Redirect URLs | `https://www.studio-canvas-ai.com/**` (+ apex) |

Instagram 전용 Redirect를 사이트에 따로 둘 필요 **없음** (provider가 facebook이므로).

---

### 2.2 Scopes / Instagram·Facebook 권한 승인 누락

#### 증상
- `Invalid Scopes: email` (초기 `email,public_profile` 시도 시)  
- Instagram “비즈니스 권한” 문서를 보고 `instagram_basic`, `pages_show_list` 등을 로그인 scope에 넣으려다 실패

#### 원인
1. Meta Use case에 **email** 미승인 상태에서 email scope 명시  
2. **Instagram Graph(비즈니스)** 권한을 **웹 로그인**에 혼용

#### 해결 (현재)
- 앱 `signInWithOAuth`에 **scopes 미지정**  
- email 없으면 synthetic `@users.facebook.id` + Supabase “Allow users without an email”  
- 미디어/인사이트용 IG Graph 권한은 **로그인 플로우에 추가하지 않음**

---

### 2.3 비즈니스 / 크리에이터 계정 연동 이슈

#### 증상·오해
- “Instagram으로 계속하기인데 비즈니스 계정이 필요하다”  
- “Facebook Page를 Instagram에 연결해야만 로그인이 된다”  
- Instagram-only 계정(페이스북 미연결)에서 기대한 UX와 Meta 다이얼로그가 다름

#### 원인 분석
이 앱은 **Instagram Graph Business Login**이 아닙니다.

| 기대 (잘못된) | 실제 |
|---------------|------|
| IG Business/Creator + Page 연결 필수 | Facebook Login으로 Meta 신원 확인 |
| IG Graph 토큰으로 `/me/media` | 미사용 |
| Supabase custom Instagram | 미사용 |

#### 해결·가이드
- 사용자에게: Meta/Facebook Login 동의 화면이 뜨는 것이 **정상**  
- Page·Creator 연결은 **콘텐츠 API**가 필요할 때만 (본 제품 로그인 범위 밖)  
- Instagram-only 유저 지원이 제품 요구가 되면, 그때 Meta의 **Instagram 제품 로그인** 별도 설계 검토 — **현 코드베이스는 해당 경로 없음**

---

### 2.4 `custom:instagram` 시도로 인한 실패 (역사적)

#### 증상
- provider not enabled / Instagram 버튼만 깨짐

#### 원인
초기 매핑 초안: `instagram → custom:instagram`. Supabase에 커스텀 미구성 시 실패.

#### 해결
```ts
instagram: "facebook"
export const signInWithInstagram = signInWithFacebook;
```
README: *Do not configure a separate Supabase Instagram custom provider for site login.*

---

### 2.5 토큰 만료 · 세션 동기화

#### 증상
- 동의 후 bridge 실패, PKCE/cookie 오류  
- 모바일·Instagram in-app browser에서 간헐 실패

#### 원인
- www ↔ apex 불일치  
- Meta/모바일 쿠키 지연 (`BridgeClient` 재시도)  
- 앱이 Meta long-lived token을 직접 refresh하지 않음 → 만료 시 **재로그인**

#### 해결
- **www에서 OAuth 시작**  
- Redirect Allow List에 www + apex  
- Bridge session retry  
- middleware `?code=` 포워드  
- in-app 브라우저 이슈 시 외부 Safari/Chrome 유도 (운영 팁)

---

### 2.6 Auth.js Instagram 폴백과의 혼선

#### 증상
- `INSTAGRAM_CLIENT_ID`만 채우고 Supabase Facebook은 비활성 → 주 경로 실패

#### 해결
- 프로덕션 주 경로: **Supabase → Providers → Facebook** (App ID/Secret)  
- `INSTAGRAM_*` / Auth.js Instagram은 **폴백·레거시**  
- `.env.example` 주석과 동일하게 문서화

| App Domains | 권장 | `studio-canvas-ai.com`, `www…` |

### 3.2 환경 변수 표준

| 변수 | 위치 | 용도 |
|------|------|------|
| App ID / App Secret | **Supabase → Facebook** | Instagram 버튼 포함 **전체 Meta 로그인** |

Secret → `NEXT_PUBLIC_*` 금지.

### 3.3 세션 생명주기 · 프로필 정규화

```
1. Instagram CTA → OAuth(facebook) + PKCE
2. Meta dialog → code → Supabase
3. Token + Graph profile (Facebook Login)
4. auth.users
5. App PKCE → cookies
6. Bridge → NextAuth JWT
7. extractSupabaseOAuthProfile
     - IdP provider string often "facebook"
     - UI may still show Instagram entry
     - email fallback @users.facebook.id
8. Local user / credits
```

| 소스 | 앱 필드 |
|------|---------|
| Meta/FB `id` / sub | `facebookSub`, synthetic email |
| email (optional) | `email` |
| name / picture | `name` / `image` |
| Supabase `user.id` | `providerAccountId` |

`mapSupabaseProviderToAuthId`는 문자열에 `instagram`이 있으면 `"instagram"`으로 매핑할 수 있으나, **실제 Supabase provider는 facebook**인 경우가 정상입니다.

## 4. 범용 아키텍처 가이드 (Reusable Blueprint)

### 4.1 의사결정 트리

```
사이트 「Instagram으로 계속하기」만 필요한가?
  ├─ YES → Facebook Login + UI 라벨 Instagram
  │         (Studio Canvas 패턴) ✅
  └─ NO, IG 미디어/인사이트도 필요?
        → Instagram Graph (Business/Creator) + Page 연동
           별도 제품·권한·토큰 설계 (본 가이드 범위 밖)
```

### 4.2 최소 구현 체크리스트

1. Meta 앱 + **Facebook Login** ON  
2. Redirect URI = Supabase callback  
3. Supabase Facebook Provider + Allow users without email  
4. UI 버튼 Instagram + `signInWithOAuth({ provider: 'facebook' })`  
5. `signInWithInstagram` alias  
6. **`custom:instagram` 만들지 않기**  
7. email scope는 Use case 승인 전 금지  
8. `/auth/callback` → bridge, www에서 시작

### 4.3 권장 소스 패턴

```ts
const TO_SUPABASE = {
  facebook: "facebook",
  instagram: "facebook", // unified Meta login
} as const;

export async function signInWithFacebook(next = "/app") {
  try {
    if (!isSupabaseConfigured()) throw new Error("Supabase not configured");
    saveNext(next);
    const supabase = createBrowserClient();
    const { data, error } = await supabase.auth.signInWithOAuth({
      provider: "facebook",
      options: {
        redirectTo: `${window.location.origin}/auth/callback?next=${encodeURIComponent(next)}`,
        // no scopes: "email" until Meta grants it
      },
    });
    if (error) {
      console.error("Meta/Facebook login error:", error.message);
      return { error };
    }
    return { data, error: null };
  } catch (e) {
    const message = e instanceof Error ? e.message : String(e);
    console.error("Meta/Facebook login error:", message);
    return { error: new Error(message) };
  }
}

export const signInWithInstagram = signInWithFacebook;
```

```tsx
// AuthModal
if (id === "facebook" || id === "instagram") {
  void handleMetaLogin(); // both call signInWithFacebook
}
```

### 4.4 Anti-patterns

| Anti-pattern | 결과 |
|--------------|------|
| Instagram Graph Business를 “로그인”으로 착각 | 불필요 권한·계정 유형 장벽 |
| `custom:instagram` 필수화 | Dashboard 누락 시 버튼만 실패 |
| Meta Redirect = 사이트 URL | token 교환 실패 |
| `scopes: "email"` 미승인 | Invalid Scopes |
| Auth.js `INSTAGRAM_*`만 설정 | 주 경로(Supabase)와 불일치 |
| IG in-app browser 무시 | PKCE/쿠키 간헐 실패 |
| 푸터 Instagram URL과 OAuth 혼동 | 잘못된 디버깅 |

### 4.5 검증 시나리오

- [ ] Instagram 버튼 → Meta 동의 → 앱 세션  
- [ ] Facebook 버튼과 **동일** Redirect/Provider 설정으로 성공  
- [ ] Supabase에 Instagram Custom provider **없음**  
- [ ] email 없는 계정 → synthetic email  
- [ ] www / 모바일  
- [ ] Instagram Graph 제품 없이도 로그인 가능

## 7. FAQ

**Q. Instagram Graph API를 켜야 「Instagram으로 계속하기」가 되나요?**  
A. 아니요. Facebook Login + Supabase Facebook provider면 충분합니다.

**Q. 왜 동의 화면이 Facebook처럼 보이나요?**  
A. IdP가 Facebook Login이기 때문입니다. UI 브랜드만 Instagram입니다.

**Q. Instagram 비즈니스 계정이 필수인가요?**  
A. 이 로그인 경로에서는 아닙니다. Business/Creator+Page는 Graph 콘텐츠 API용입니다.

**Q. `INSTAGRAM_CLIENT_SECRET`을 Vercel에 넣어야 하나요?**  
A. 주 경로에서는 아니요. Supabase Facebook에 App Secret만 있으면 됩니다.

**Q. 가장 흔한 재발 원인 3가지?**  
A. (1) Instagram을 별도 Custom OAuth로 구성 (2) Redirect를 사이트에 등록 (3) 미승인 email/IG Graph scope를 로그인에 추가
