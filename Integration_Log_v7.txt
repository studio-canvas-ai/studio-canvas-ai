# 마이크로소프트로 계속하기 (Microsoft Identity Platform / OIDC) 연동 완벽 가이드

> Studio Canvas AI (Next.js) — **「Microsoft로 계속하기」**  
> 기준 코드: `signInWithMicrosoft` (`custom:microsoft`), AuthModal, `/auth/callback` → `/auth/bridge`  
> 최종 정리일: 2026-08-08  
> 파일: `Integration_Log_v7.txt` (프로젝트 Root)

## 0. 한 줄 요약 (현재 아키텍처)

| 항목 | 실제 구현 |
|------|-----------|
| 프로토콜 | **OAuth 2.0 Authorization Code** + **OpenID Connect** + **PKCE** |
| IdP | **Microsoft Entra ID** (Azure AD) — `login.microsoftonline.com` |
| 주 경로 | Supabase **Custom OAuth** — `provider: "custom:microsoft"` |
| 테넌트 | **`common`** (개인 MSA + 모든 조직 디렉터리) — 고정 tenant ID 금지 |
| 프론트 진입 | `AuthModal` → `signInWithMicrosoft()` |
| Azure Redirect URI | `https://oorujqbivznftsyqilyj.supabase.co/auth/v1/callback` |
| 앱 `redirectTo` | `${origin}/auth/callback?next=…` (`buildAuthCallbackRedirectTo`) |
| Scopes (앱) | `openid profile email offline_access` |
| Userinfo | `https://graph.microsoft.com/oidc/userinfo` (Dashboard; GoTrue 호출) |
| 대표 오류 | **AADSTS70016** (고정 테넌트 불일치) |
| 폴백 | Auth.js `MicrosoftEntraID` + `MICROSOFT_ISSUER=…/common/v2.0` |

앱은 Microsoft Graph REST(`User.Read`로 `/v1.0/me` 등)를 **직접 호출하지 않습니다.**  
프로필은 OIDC userinfo(및 id_token claims)를 **Supabase GoTrue**가 수집합니다.

## 1. 핵심 파일 구조 및 라우팅

### 1.1 프론트엔드 트리거 · 인증 요청 진입점

| 경로 | 역할 |
|------|------|
| `components/AuthModal.tsx` | Microsoft 버튼, `MicrosoftLogo`, `handleMicrosoftLogin` |
| `lib/supabase/oauth.ts` | **`signInWithMicrosoft`**, `TO_SUPABASE.microsoft = "custom:microsoft"`, provider 매핑 |
| `lib/supabase/client.ts` | 브라우저 Supabase 클라이언트 |
| `lib/i18n/locales/*` | `continueWithMicrosoft` |
| `components/CreditsProvider.tsx` | `"microsoft"` provider 타입 |

**버튼 → OAuth:**

```
handleMicrosoftLogin()
  setBusy(true)
  try
    next ← resolveAuthNext()
    signInWithMicrosoft(next)
      → saveAuthNextPath(next)
      → supabase.auth.signInWithOAuth({
           provider: "custom:microsoft",
           options: {
             redirectTo: buildAuthCallbackRedirectTo(next),
             scopes: "openid profile email offline_access",
           },
         })
    (성공) Microsoft로 이동 — busy 유지
  catch → console.error("예기치 못한 오류…") / "마이크로소프트 로그인 오류:"
```

### 1.2 콜백 · 토큰 · OIDC / Graph userinfo 라우트

| 경로 | 역할 |
|------|------|
| **Entra Redirect URI (Web)** | `https://oorujqbivznftsyqilyj.supabase.co/auth/v1/callback` |
| Supabase GoTrue | code → token (+ refresh via `offline_access`) → OIDC userinfo → `auth.users` |
| `middleware.ts` | Site `/` + `?code=` → `/auth/callback` (origin만으로 돌아올 때) |
| `app/auth/callback/route.ts` | PKCE `exchangeCodeForSession` → `/auth/bridge` |
| `lib/supabase/exchange.ts` | 세션 쿠키 |
| `app/auth/bridge/*` | Supabase 세션 → `/api/auth/supabase-bridge` |
| `app/api/auth/supabase-bridge/route.ts` | NextAuth JWT + 앱 유저 |
| `lib/auth.ts` | Auth.js `MicrosoftEntraID` 폴백 (`id: "microsoft"`, issuer `common`) |

**앱에 Microsoft token/userinfo 전용 API Route는 없습니다.**  
Authorize/Token/Issuer/JWKS/Userinfo URL은 **Supabase Dashboard Custom Provider**에만 존재합니다 (코드 하드코딩 없음).

### 1.3 Token Exchange / OIDC 로직 구조

```
[Browser]
  AuthModal → signInWithMicrosoft
       │  provider = custom:microsoft
       ▼
[Entra ID]  /common/oauth2/v2.0/authorize
            (client_id, redirect_uri=Supabase callback, scope, state, PKCE)
       │
       ▼
[Supabase]  /auth/v1/callback?code=…
       │  1) state / PKCE 검증
       │  2) POST …/common/oauth2/v2.0/token  (code → access_token, id_token, refresh_token)
       │  3) GET https://graph.microsoft.com/oidc/userinfo
       │       Authorization: Bearer <access_token>
       │  4) JWKS로 id_token 검증 (issuer = …/common/v2.0)
       │  5) auth.users upsert
       │  6) 앱 redirectTo 로 PKCE code
       ▼
[App]  /auth/callback?code=…&next=…
       │  exchangeSupabaseCode
       ▼
[App]  /auth/bridge → NextAuth session
```

**Scopes 해석**

| Scope | 역할 |
|-------|------|
| `openid` | OIDC id_token |
| `profile` | 이름 등 기본 프로필 |
| `email` | 이메일 claim |
| `offline_access` | refresh_token (GoTrue 세션 갱신에 유리) |

`User.Read`(Microsoft Graph 위임 권한)는 **별도 Graph REST**용입니다.  
현 로그인은 OIDC userinfo로 충분하며, 앱 코드에 `User.Read`를 넣지 않습니다. Dashboard/앱 등록에서 Graph 권한을 과도하게 요구하면 관리자 동의 장벽만 커질 수 있습니다.

### 1.4 엔드투엔드

```
User → Microsoft CTA
     → Entra (common) consent
     → Supabase token + oidc/userinfo
     → /auth/callback → /auth/bridge
     → /generate ± terms-consent
```

## 2. 트러블슈팅 및 에러 핸들링

### 2.1 Redirect URI 불일치

#### 증상
- `AADSTS50011` / redirect URI mismatch  
- 동의 후 잘못된 호스트

#### 올바른 삼각 관계

| 위치 | 값 |
|------|-----|
| **Entra** Web Redirect URI | `https://oorujqbivznftsyqilyj.supabase.co/auth/v1/callback` |
| **앱 `redirectTo`** | `https://www.studio-canvas-ai.com/auth/callback?next=…` |
| **Supabase** Redirect URLs | `https://www.studio-canvas-ai.com/**` |

#### 흔한 실수

| 잘못된 설정 | 결과 |
|-------------|------|
| Entra Redirect = 사이트 `/auth/callback` | GoTrue가 code를 못 받음 |
| 앱 `redirectTo` = 사이트의 `/auth/v1/callback` | 존재하지 않는 앱 경로 / 혼동 (README 경고) |
| Entra Redirect = Auth.js `/api/auth/callback/microsoft` | 주 경로(Supabase)와 단절 |

---

### 2.2 테넌트(Tenant) 유형 오류 — **AADSTS70016**

#### 증상
- `AADSTS70016`: 앱이 해당 디렉터리에 없음  
- 회사 계정은 되고 개인 Microsoft 계정은 실패(또는 그 반대)  
- 특정 조직만 로그인 가능

#### 원인
Supabase Custom Provider의 Authorization / Token / Issuer / JWKS에 **고정 디렉터리(tenant) GUID**를 넣음:

```text
https://login.microsoftonline.com/<tenant-guid>/oauth2/v2.0/authorize  ← 문제
```

Entra 앱 등록의 “Supported account types”가 **단일 테넌트**인데 `common`으로 호출하거나, 그 반대 불일치.

#### 해결 (필수)

Dashboard 엔드포인트를 모두 **`common`** 으로 통일:

| Field | Value |
|--------|--------|
| Authorization | `https://login.microsoftonline.com/common/oauth2/v2.0/authorize` |
| Token | `https://login.microsoftonline.com/common/oauth2/v2.0/token` |
| Issuer | `https://login.microsoftonline.com/common/v2.0` |
| JWKS | `https://login.microsoftonline.com/common/discovery/v2.0/keys` |

Entra 앱: **Accounts in any organizational directory and personal Microsoft accounts**.

Auth.js 폴백: `MICROSOFT_ISSUER` 기본값 동일 `…/common/v2.0`.

코드 주석(`signInWithMicrosoft`)에 AADSTS70016 방지 가이드가 명시되어 있습니다.

---

### 2.3 Scopes / 권한 승인 누락

#### 증상
- consent 오류, email/profile 누락, admin consent 요구

#### 원인·대응

| 이슈 | 대응 |
|------|------|
| OIDC scope 누락 | 앱: `openid profile email offline_access` 유지 |
| `User.Read`를 로그인에 강제 | 불필요하면 제거; OIDC userinfo로 충분 |
| 조직에서 외부 앱 차단 | 테넌트 관리자 동의 또는 허용 목록 |
| email claim 없음 | Supabase “Allow users without an email” + 앱 프로필 폴백 |

Naver와 달리 Microsoft는 **`openid`를 포함**하는 것이 정상(OIDC)입니다.  
(`custom:naver`는 `openid` 넣으면 userinfo 스킵 — 혼동 주의, `Integration_Log_v3.txt`)

---

### 2.4 토큰 만료 · 세션 동기화

#### 증상
- Entra 동의 후 bridge 실패, `missing_code`, PKCE verifier 오류

#### 원인
- www ↔ apex  
- `redirectTo`를 origin만 쓰고 middleware 포워드에만 의존하다 code 유실 (현재 코드는 `/auth/callback?next=` 명시)  
- refresh 없이 장기 방치 후 API 401

#### 해결
- `buildAuthCallbackRedirectTo` 사용 (현 코드)  
- Redirect Allow List + www에서 시작  
- `offline_access`로 refresh_token 확보 (GoTrue)  
- Bridge retry + middleware code 포워드  
- 만료 시 재로그인 (앱이 Entra token을 직접 refresh하지 않음)

---

### 2.5 Custom provider id 오타

#### 증상
- Provider not enabled / unsupported provider

#### 해결
- Dashboard identifier: **`microsoft`**  
- 앱 호출: **`custom:microsoft`** (접두사 `custom:` 필수)  
- 과거 초안의 built-in `azure` 매핑은 **폐기** — 현재 `TO_SUPABASE.microsoft = "custom:microsoft"`

## 4. 범용 아키텍처 가이드 (Reusable Blueprint)

### 4.1 설계 원칙

1. Microsoft는 Supabase **Custom OAuth**로 붙인다 (`custom:<id>`)  
2. 다중 계정 지원 시 엔드포인트·앱 등록 모두 **`common`**  
3. Redirect는 **항상** `https://<ref>.supabase.co/auth/v1/callback`  
4. 앱 `redirectTo`는 사이트 `/auth/callback` (IdP callback과 혼동 금지)  
5. 로그인 scope는 OIDC 최소 세트; Graph `User.Read`는 필요할 때만  
6. URL은 Dashboard에만 — 앱 코드에 tenant URL 하드코딩 지양

### 4.2 최소 구현 체크리스트

1. Entra 앱 등록 (multi-tenant + MSA)  
2. Redirect URI = Supabase callback  
3. Client secret 발급 → Supabase Custom `microsoft`  
4. common authorize/token/issuer/jwks + oidc userinfo  
5. Scopes: `openid profile email offline_access`  
6. `signInWithOAuth({ provider: 'custom:microsoft', … })`  
7. `/auth/callback` + bridge  
8. AADSTS70016 재현 테스트: 개인 계정 + 타 조직 계정

### 4.3 권장 소스 패턴

```ts
export async function signInWithMicrosoft(next = "/app") {
  try {
    if (!isSupabaseConfigured()) throw new Error("Supabase not configured");
    saveNext(next);
    const supabase = createBrowserClient();
    const { data, error } = await supabase.auth.signInWithOAuth({
      provider: "custom:microsoft",
      options: {
        redirectTo: `${window.location.origin}/auth/callback?next=${encodeURIComponent(next)}`,
        scopes: "openid profile email offline_access",
      },
    });
    if (error) {
      console.error("마이크로소프트 로그인 오류:", error.message);
      return { error };
    }
    return { data, error: null };
  } catch (e) {
    console.error("예기치 못한 오류가 발생했습니다:", e);
    return { error: e instanceof Error ? e : new Error(String(e)) };
  }
}
```

### 4.4 Anti-patterns

| Anti-pattern | 결과 |
|--------------|------|
| Token/Issuer에 tenant GUID 고정 | **AADSTS70016** |
| Entra를 single-tenant로 두고 common 호출 | 계정 유형 오류 |
| Redirect = 사이트 URL | code/token 주체 붕괴 |
| 앱 redirectTo = `/auth/v1/callback` on site | 잘못된 경로 |
| Naver처럼 `openid` 제거 | OIDC userinfo/id_token 깨짐 |
| `User.Read` 필수화(로그인만) | 불필요 admin consent |
| Secret 프론트 노출 | 보안 사고 |

### 4.5 Auth.js 폴백

```ts
MicrosoftEntraID({
  id: "microsoft",
  clientId: process.env.MICROSOFT_CLIENT_ID,
  clientSecret: process.env.MICROSOFT_CLIENT_SECRET,
  issuer:
    process.env.MICROSOFT_ISSUER ||
    "https://login.microsoftonline.com/common/v2.0",
})
```

주 경로는 Supabase Custom. Entra Redirect는 Supabase callback 유지.

### 4.6 검증 시나리오

- [ ] 개인 Microsoft 계정 로그인  
- [ ] 타 조직 직장/학교 계정 로그인 (AADSTS70016 없음)  
- [ ] Redirect mismatch 없음  
- [ ] bridge → 앱 세션 + 이메일/이름  
- [ ] www / localhost Redirect Allow List  
- [ ] Dashboard URL이 모두 `common`

## 7. FAQ

**Q. built-in `azure` provider를 쓰나요?**  
A. 아니요. 코드는 **`custom:microsoft`** 입니다.

**Q. `User.Read`가 꼭 필요한가요?**  
A. 이 앱 로그인만으로는 아닙니다. OIDC userinfo로 프로필을 받습니다.

**Q. 왜 Naver는 openid를 빼는데 Microsoft는 넣나요?**  
A. Naver는 nested userinfo 프록시 강제용 예외. Microsoft는 표준 OIDC라 `openid`가 맞습니다.

**Q. 가장 흔한 재발 원인 3가지?**  
A. (1) 고정 tenant → AADSTS70016 (2) Redirect를 사이트에 등록 (3) 앱 redirectTo를 Supabase callback 경로와 혼동
