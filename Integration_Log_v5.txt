```text
UI "facebook"  → Supabase provider "facebook"
UI "instagram" → Supabase provider "facebook"   // Meta unified
```

**버튼 → OAuth 시작:**

```
handleMetaLogin()   // Facebook & Instagram 공통
  setBusy(true)
  try
    next ← resolveAuthNext()
    signInWithFacebook(next)
      → saveAuthNextPath(next)
      → supabase.auth.signInWithOAuth({
           provider: "facebook",
           options: {
             redirectTo: `${origin}/auth/callback?next=…`,
             skipBrowserRedirect: false,  // SDK가 Meta로 이동
             // scopes 미지정 — email 명시 금지 (아래 2.3)
           },
         })
  catch → console.error("Meta/Facebook login error:") + UI
```

### 1.3 Token Exchange / Graph API 로직 구조

```
[Browser]
  AuthModal → signInWithFacebook
       │  Supabase SDK redirect → Meta dialog
       ▼
[Meta]  Facebook Login (OAuth dialog)
       │  redirect_uri = Supabase /auth/v1/callback
       ▼
[Supabase GoTrue]
       │  1) state / PKCE 검증
       │  2) Meta token endpoint (code → access_token)
       │  3) Graph API (버전은 GoTrue/Meta 앱 설정에 따름)
       │       전형적: GET /{graph-version}/me?fields=id,name,email,picture…
       │  4) auth.users upsert (email 없을 수 있음)
       │  5) 앱 redirectTo 로 PKCE code 전달
       ▼
[App]  /auth/callback → exchangeSupabaseCode
       ▼
[App]  /auth/bridge → getSession (retry) → POST /api/auth/supabase-bridge
       ▼
[App]  extractSupabaseOAuthProfile → provider=facebook, synthetic email 폴백
```

**이중 code**

| Code | 소비자 | 용도 |
|------|--------|------|
| Meta → Supabase | GoTrue | access_token + Graph `/me` |
| Supabase → App | `/auth/callback` | 브라우저 Supabase 세션 쿠키 |

### 1.4 엔드투엔드 시퀀스

```
User → AuthModal (Facebook or Instagram UI)
     → Meta consent
     → Supabase token + Graph profile
     → /auth/callback (PKCE)
     → /auth/bridge (session mint; cookie race tolerant)
     → /generate ± terms-consent
```

## 2. 트러블슈팅 및 에러 핸들링

### 2.1 Redirect URI 불일치

#### 증상
- Meta: “URL Blocked” / redirect_uri 오류  
- 동의 후 잘못된 호스트로 복귀

#### 올바른 삼각 관계

| 위치 | 값 |
|------|-----|
| **Meta** Valid OAuth Redirect URIs | `https://oorujqbivznftsyqilyj.supabase.co/auth/v1/callback` |
| **Meta** App Domains | `studio-canvas-ai.com`, `www.studio-canvas-ai.com` |
| **앱 `redirectTo`** | `https://www.studio-canvas-ai.com/auth/callback?next=…` |
| **Supabase Redirect URLs** | `https://www.studio-canvas-ai.com/**`, apex `/**` |

잘못: Meta Redirect에 사이트 `/auth/callback` 또는 `/api/auth/callback/facebook`만 등록.  
→ code는 **Supabase**가 받아야 token/Graph 단계가 진행됩니다.

---

### 2.2 Graph API 버전 · 호환성

#### 증상
- 로그인 중 GoTrue/Meta 측 필드 누락, deprecated endpoint 경고 (대시보드/로그)

#### 원인·원칙
- Graph API 버전은 **앱 Next.js가 고정하지 않음** — Supabase Facebook provider + Meta 앱 설정이 결정
- Meta는 주기적으로 Graph 버전을 폐기(deprecate). 로그인만 쓰는 경우 필드는 보통 `id`, `name`, `email`, `picture` 수준
- 앱이 `/vXX.X/me`를 하드코딩하면 버전 드리프트에 취약 → **의도적으로 GoTrue에 위임**

#### 해결
- Meta 개발자 콘솔에서 앱이 지원하는 Graph API 버전·Login 제품 상태 확인  
- Supabase Facebook provider를 최신으로 유지  
- 앱 측에서는 Graph 버전 상수를 **추가하지 않음** (현 아키텍처 유지)  
- 필드 부족 시 synthetic email + name/picture 폴백으로 브리지 성공 유지

---

### 2.3 Permissions / Scopes — `Invalid Scopes: email`

#### 증상
- Meta/Supabase 오류: **`Invalid Scopes: email`**  
- 초기 구현에서 `scopes: "email,public_profile"`를 넣었을 때 재현

#### 원인
Meta **Use cases → Authentication**에 **email** 권한이 아직 없거나 Advanced Access 미승인인 상태에서 authorize URL에 `email` scope를 명시하면 거부됩니다.

#### 해결 (현재 코드)
1. `signInWithFacebook`에서 **`scopes` 옵션을 넣지 않음** (기본 public profile 경로)  
2. 이메일 미제공 허용:  
   - Supabase **Allow users without an email**  
   - `extractSupabaseOAuthProfile`: `` `${facebookSub}@users.facebook.id` ``  
3. 나중에 Meta에서 email Use case가 승인되면 그때 `scopes`에 email 추가 검토 (승인 전 재삽입 금지)

---

### 2.4 Instagram을 `custom:instagram`로 분리했을 때의 함정

#### 증상
- Instagram 버튼만 실패 / provider not enabled

#### 원인
초기에 `instagram → custom:instagram` 매핑을 검토했으나, 사이트 로그인은 **Facebook Login 하나로 Meta가 FB/IG 계정을 처리**하는 편이 안정적.

#### 해결
- `instagram: "facebook"`  
- `signInWithInstagram = signInWithFacebook`  
- **별도 Supabase Instagram Custom Provider 구성하지 않음**  
- Auth.js `INSTAGRAM_*`는 폴백 전용

---

### 2.5 토큰 만료 · 세션 동기화

#### 증상
- Meta 동의 성공 후 bridge 실패, “No Supabase access token”  
- 모바일 / in-app 브라우저에서 간헐 실패

#### 원인
- www ↔ apex PKCE 쿠키 불일치  
- Facebook/모바일에서 세션 쿠키가 **한 틱 늦게** 기록 (`BridgeClient` 주석)  
- access token 만료 후 재로그인 필요 (앱은 Meta long-lived token을 직접 갱신하지 않음 — 다음 OAuth로 재발급)

#### 해결
- OAuth는 **www에서 시작** (README: PKCE host match)  
- Redirect Allow List에 www + apex  
- Bridge: `SESSION_ATTEMPTS` + 짧은 backoff (Facebook cookie race)  
- middleware code 포워드  
- 재로그인으로 새 Supabase 세션 발급 (앱에 Meta token refresh API 없음)

---

## 4. 범용 아키텍처 가이드 (Reusable Blueprint)

### 4.1 설계 원칙

1. **Facebook Login 하나로 FB + IG UI 통합** — 별도 Instagram Custom OAuth 지양  
2. **Graph는 IdP 어댑터(GoTrue)에 위임** — 앱에 `/me` 프록시 최소화  
3. **승인되지 않은 scope는 절대 문자열로 넣지 않음**  
4. **이메일 없는 계정**을 synthetic address + dashboard 플래그로 허용  
5. Google/Kakao와 동일한 callback → bridge 파이프라인 재사용

### 4.2 최소 구현 체크리스트

1. Meta 앱 생성 + Facebook Login 제품 ON  
2. Valid OAuth Redirect URI = `https://<ref>.supabase.co/auth/v1/callback`  
3. App Domains / HTTPS / Privacy URL  
4. Supabase Facebook Provider + Allow users without email  
5. Redirect Allow List에 site `/**`  
6. `signInWithOAuth({ provider: 'facebook', options: { redirectTo } })` — **email scope 보류**  
7. Instagram 버튼도 동일 함수  
8. `/auth/callback` + bridge + www에서 시작

### 4.3 권장 소스 패턴

```ts
export async function signInWithFacebook(next = "/app") {
  try {
    if (!isSupabaseConfigured()) throw new Error("Supabase not configured");
    saveNext(next);
    const supabase = createBrowserClient();
    const { data, error } = await supabase.auth.signInWithOAuth({
      provider: "facebook",
      options: {
        redirectTo: `${window.location.origin}/auth/callback?next=${encodeURIComponent(next)}`,
        // Do NOT set scopes: "email" until Meta Use case grants email.
      },
    });
    if (error) {
      console.error("Meta/Facebook login error:", error.message);
      return { error };
    }
    return { data, error: null };
  } catch (e) {
    const message = e instanceof Error ? e.message : String(e);
    console.error("Meta/Facebook login error:", message);
    return { error: new Error(message) };
  }
}

export const signInWithInstagram = signInWithFacebook;
```

### 4.4 Anti-patterns

| Anti-pattern | 결과 |
|--------------|------|
| Meta Redirect = 사이트 URL | token/Graph 주체 붕괴 |
| `scopes: "email"` (미승인) | `Invalid Scopes: email` |
| `custom:instagram` 필수화 | 이중 설정·실패 증가 |
| 앱에서 Graph 버전 하드코딩 | 버전 폐기 시 단독 장애 |
| Secret을 프론트에 노출 | 보안 사고 |
| apex에서 시작 / www로 callback | PKCE 실패 |
| email 필수만 가정 | 이메일 없는 FB 계정 로그인 불가 |

## 7. FAQ

**Q. 앱에서 Graph API를 직접 호출해야 하나요?**  
A. 로그인 목적만이면 아니요. GoTrue가 token + `/me`를 처리합니다.

**Q. Instagram 전용 Client ID가 필요한가요?**  
A. 이 사이트 로그인에는 아니요. Facebook Login으로 통합합니다.

**Q. 언제 `scopes: "email"`을 넣나요?**  
A. Meta Use cases에서 email이 앱에 허용된 뒤에만. 그전에는 Invalid Scopes가 납니다.

**Q. Google/Naver와 차이는?**  
A. Google: first-class + email scope 기본 OK. Naver: custom + nested userinfo 프록시. Facebook: first-class이나 **email scope 조심** + synthetic email.

**Q. 가장 흔한 재발 원인 3가지?**  
A. (1) Meta Redirect 오등록 (2) 미승인 email scope (3) www/apex PKCE 불일치
