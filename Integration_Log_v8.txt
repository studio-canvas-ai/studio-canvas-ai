## 0. 한 줄 요약 (현재 아키텍처)

| 항목 | 실제 구현 |
|------|-----------|
| 프로토콜 | **OAuth 2.0 Authorization Code** + **PKCE** |
| IdP | **Kakao Developers** (카카오 로그인) — `kauth.kakao.com` / `kapi.kakao.com` |
| 주 경로 | Supabase **built-in Kakao** — `provider: "kakao"` (**`custom:kakao` 사용 금지**) |
| 프론트 진입 | `AuthModal` → `handleKakaoLogin` → `signInWithKakao()` |
| Kakao Redirect URI | `https://oorujqbivznftsyqilyj.supabase.co/auth/v1/callback` |
| 앱 `redirectTo` | `${origin}/auth/callback?next=…` (`buildAuthCallbackRedirectTo`) — 기본 `next=/` |
| Scopes (앱) | `queryParams.scope = "profile_nickname,profile_image"` (**`account_email` 미요청**) |
| 이메일 정책 | Supabase **Allow users without an email** + 합성 `{kakaoId}@users.kakao.id` |
| 대표 오류 | **KOE006** (redirect_uri 불일치) · **KOE205** (`account_email` 동의 항목) |
| Canonical project | `oorujqbivznftsyqilyj` — 테스트 ref `ysdccsfpxduqcqxgwuy` **폐기** |
| 폴백 | Auth.js `Kakao` (`KAKAO_CLIENT_ID` / `SECRET`) — Supabase 미구성 시에만 |

앱은 Kakao REST(`kapi.kakao.com/v2/user/me`)를 **로그인 주경로에서 직접 호출하지 않습니다.**  
토큰 교환·유저 수집은 **Supabase GoTrue**가 담당합니다.  
(선택) `kakao-userinfo` Edge Function / `/api/auth/kakao/userinfo`는 실험용으로만 존재합니다.

**카카오 로그인(OAuth)** 과 **카카오톡 공유(JS SDK)** 는 별개입니다.  
공유는 `lib/kakaoShare.ts`의 JavaScript 키를 쓰며, 로그인 REST API Key와 혼동하지 마세요.

## 2. 트러블슈팅 및 에러 핸들링 (Troubleshooting & Edge Cases)

### 2.1 KOE006 — Redirect URI 불일치 (치명적)

**증상**

- 카카오 로그인 화면에서 `KOE006` / “등록되지 않은 redirect_uri” / 앱 관리자 설정 오류
- 브라우저 Network의 authorize URL `redirect_uri`가 예상과 다름

**근본 원인 (Studio Canvas에서 실제로 겪은 것)**

1. **Kakao가 보는 `redirect_uri`는 앱 `redirectTo`가 아니다.**  
   GoTrue가 항상 `https://<NEXT_PUBLIC_SUPABASE_URL의 project-ref>.supabase.co/auth/v1/callback` 을 Kakao에 넘긴다.
2. Vercel Production의 `NEXT_PUBLIC_SUPABASE_URL` / `ANON_KEY`가 **비어 있거나 예시·오타·다른 프로젝트**였음.
3. **프로젝트 2개 혼선**
   - 본체(정식): `oorujqbivznftsyqilyj` (모든 소셜 + 데이터)
   - 테스트(폐기): `ysdccsfpxduqcqxgwuy` (DNS NXDOMAIN / 잘못된 콜백)
4. Kakao Developers에 **Default 앱 REST Key**와 **Studio Canvas용 앱**이 섞여,  
   Supabase에 넣은 Key와 Redirect URI를 등록한 앱이 **서로 다른 앱**이었을 가능성.

**해결 체크리스트**

| # | 확인 |
|---|------|
| 1 | Vercel Production: `NEXT_PUBLIC_SUPABASE_URL=https://oorujqbivznftsyqilyj.supabase.co` |
| 2 | 동일 프로젝트의 Publishable/Anon Key |
| 3 | `NEXT_PUBLIC_*` 변경 후 **반드시** `vercel --prod` 재배포 |
| 4 | Kakao Developers → **그 REST Key가 속한 앱** → Redirect URI에  
   `https://oorujqbivznftsyqilyj.supabase.co/auth/v1/callback` **정확히 1줄** |
| 5 | 사이트 origin(`https://www.studio-canvas-ai.com/**`)은 **Supabase Auth Redirect URLs**에 등록 (Kakao 콘솔이 아님) |
| 6 | 로컬 `.env.local`도 동일 canonical ref (로컬만 틀려도 KOE006 재현) |

**코드 방어**

- `lib/supabase/config.ts` — `RETIRED_SUPABASE_PROJECT_REFS`에 `ysdccsfpxduqcqxgwuy` → URL 정규화 단계에서 **거부**
- `getSupabaseConfigError()` — retired URL이면 canonical 안내 메시지
- `authStorage.ensureSupabaseAuthStorageReady()` — `sb-ysdccsf…-*` 쿠키/키 퍼지
- OAuth 직전(Kakao/Google 등) 동일 퍼지 호출

**진단 한 줄**

> Kakao 콘솔 Redirect URI ≡ GoTrue가 보내는 URI ≡ `NEXT_PUBLIC_SUPABASE_URL`의 project-ref.  
> 셋 중 하나라도 어긋나면 KOE006.

### 2.2 KOE205 / “Error getting user email from external provider”

**증상**

- KOE205: 동의 항목 `account_email` 미설정 / 개인 앱에서 이메일 스코프 불가
- Supabase: `Error getting user email from external provider`

**근본 원인**

- 개인(비비즈) 카카오 앱은 **`account_email` 동의 항목을 쓸 수 없는 경우**가 많음
- GoTrue 기본 동작은 email claim을 기대 → 없으면 실패

**해결 (현재 프로덕션 패턴)**

1. **앱 코드** — `account_email`을 요청하지 않음:

```ts
queryParams: { scope: "profile_nickname,profile_image" }
```

2. **Supabase Dashboard → Providers → Kakao**  
   - **Allow users without an email** = ON

3. **앱 브릿지** — `extractSupabaseOAuthProfile`:  
   - Kakao `id` / `sub` → `kakaoSub`  
   - email 없으면 `{kakaoSub}@users.kakao.id` (또는 `{supabaseUserId}@users.kakao.id`)

4. **UI** — `formatOAuthError`가 KOE205를 한국어 안내로 변환

**비즈 전환 시 (선택)**

- Kakao에서 `account_email` 활성화 후 scope에 추가 가능  
- 그래도 “이메일 없는 카카오 계정”이 있으므로 Allow users without an email은 유지 권장

### 2.3 Vercel env · 테스트 프로젝트 잔여물로 인한 라우팅 붕괴

**증상**

- 프로덕션 JS에 엉뚱한 ref가 박히거나, 로그인 직후 DNS/콜백 실패
- 예전 프로젝트 쿠키가 PKCE를 오염

**차단 레이어**

| 레이어 | 구현 |
|--------|------|
| Env 문서 | `.env.example`, `supabase/README.md` — canonical URL/키 명시, retired 경고 |
| Runtime URL | `normalizeSupabaseUrl` — retired ref → `undefined` |
| Storage | `purgeStaleSupabaseAuthStorage` — foreign + retired `sb-*` 제거 |
| Client init | `createSupabaseBrowserClient`가 항상 storage ready 호출 |
| Link CLI | `supabase/config.toml` → `project_id = "oorujqbivznftsyqilyj"` |

**운영 규칙**

- 소셜·DB·Edge Function은 **한 프로젝트(`oorujqb…`)만** 사용
- Preview/Production 모두 동일 URL 권장 (키가 Preview에서 테스트 ref로 바뀌면 KOE006 재발)
- 비밀키(Client Secret, service_role)는 Vercel에만 — 레포/문서에 실값 금지

### 2.4 기타 Edge Cases

| 현상 | 원인 | 대응 |
|------|------|------|
| PKCE / code verifier | www ↔ apex / localhost 혼용 | 시작·종료 동일 origin; Redirect URLs에 각 origin/** |
| `custom:kakao` 실패 | Custom provider 미구성 | **built-in `kakao`만** 사용 |
| 로그인 후 /generate | 구버전 기본 next | 현재 기본 `/` (재배포 확인) |
| 약관 페이지 먼저 | `needsTermsConsent` | 정상 — 동의 후 `next=/` |
| Auth.js 폴백과 이중 등록 | `KAKAO_CLIENT_*` + Supabase 동시 | 주경로는 Supabase; Auth.js는 폴백 |

## 3. 카카오 개발자 콘솔 연동 규격 및 보안

### 3.1 Kakao Developers 필수 설정

| 항목 | 값 / 규칙 |
|------|-----------|
| 플랫폼 | Web — 사이트 도메인 `https://www.studio-canvas-ai.com` 등 |
| 카카오 로그인 | **활성화** |
| Redirect URI | **`https://oorujqbivznftsyqilyj.supabase.co/auth/v1/callback`만** (사이트 `/auth/callback` 아님) |
| 동의 항목 | `닉네임`, `프로필 사진` (필수에 가깝게) · `계정 이메일`은 가능 시만 |
| REST API Key | → Supabase Kakao **Client ID** |
| Client Secret | 코드 활성화 ON → Supabase Kakao **Client Secret** |

**중요:** Redirect URI에 `https://www.studio-canvas-ai.com/auth/callback` 을 넣어도  
Kakao authorize의 `redirect_uri`는 Supabase 호스트이므로 **KOE006이 해결되지 않습니다.**

### 3.2 환경 변수 관리 표준

**앱(Vercel / `.env.local`) — 공개 가능 쪽**

```
NEXT_PUBLIC_SUPABASE_URL=https://oorujqbivznftsyqilyj.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<publishable or legacy anon JWT>
NEXT_PUBLIC_SITE_URL=https://www.studio-canvas-ai.com
AUTH_SECRET=<NextAuth secret>
AUTH_URL / NEXTAUTH_URL=<SITE_URL과 동일>
```

**Supabase Dashboard only (앱 env에 넣지 않음)**

```
Kakao Client ID     = Kakao REST API Key
Kakao Client Secret = Kakao Client Secret
```

**Auth.js 폴백(선택)**

```
KAKAO_CLIENT_ID=
KAKAO_CLIENT_SECRET=
```

**공유 SDK와 분리**

- `NEXT_PUBLIC_KAKAO_JS_KEY` / `lib/kakaoShare.ts` — **톡 공유용 JS 키**
- 로그인 REST Key와 **절대 혼용하지 말 것**
- 레거시 차단 키 규칙은 `lib/kakaoShare.ts` 주석 참고

### 3.3 식별자 · 프로필 정규화 · 세션 생명주기

**정규화 (`extractSupabaseOAuthProfile`)**

| 필드 | 소스 우선순위 |
|------|----------------|
| `provider` | `app_metadata.provider` / identity → `"kakao"` |
| `providerAccountId` | **항상** Supabase `user.id` (UUID) — 로컬 유저 키 |
| `kakaoSub` | `sub` / `provider_id` / `id` / `kakao_account.id` |
| `email` | 실이메일 → 없으면 `{kakaoSub}@users.kakao.id` |
| `name` | `nickname` / `properties.nickname` / `kakao_account.profile.nickname` |
| `image` | `profile_image` / thumbnail / `profile_image_url` |

**세션 생명주기**

1. Supabase Auth 세션 (PKCE cookies, `sb-<ref>-auth-token`)
2. Bridge가 access token으로 **NextAuth JWT** 발급 (앱 세션)
3. JWT `maxAge` ≈ 30일 (`lib/auth.ts`)
4. 약관 미동의 → `/terms-consent` 게이트 (middleware / bridge)
5. 로그아웃: Supabase signOut + NextAuth signOut + 관련 쿠키 정리 (`/api/auth/logout` 등)
6. 프로젝트 전환 시: `ensureSupabaseAuthStorageReady`가 이전 ref 키 제거

## 4. 범용 아키텍처 가이드 (Reusable Blueprint)

다른 Next.js + Supabase 프로젝트에 카카오 로그인을 이식할 때의 **표준 패턴**입니다.

### 4.1 결정 트리

```
Q1. Supabase built-in Kakao를 쓸 수 있는가?
  YES → provider: "kakao"  (권장, Studio Canvas 채택)
  NO  → Custom OAuth + userinfo flatten 프록시 (실험 경로만)

Q2. 카카오 앱이 개인(비비즈)인가?
  YES → scope에서 account_email 제외 + Allow users without an email + 합성 email
  NO  → email 동의 가능해도 Allow users without an email 유지 권장

Q3. Redirect URI를 어디에 등록하는가?
  Kakao Developers → https://<ref>.supabase.co/auth/v1/callback
  Supabase Redirect URLs → https://your-site.com/**  (앱 redirectTo)
```

### 4.2 최소 구현 체크리스트 (복붙용)

1. Supabase 프로젝트 1개 확정 → URL/Anon Key를 `NEXT_PUBLIC_*`에 고정  
2. Kakao 앱 1개 확정 → REST Key + Secret을 Supabase Kakao Provider에만 저장  
3. Kakao Redirect URI = `https://<ref>.supabase.co/auth/v1/callback`  
4. 프론트:

```ts
await supabase.auth.signInWithOAuth({
  provider: "kakao",
  options: {
    redirectTo: `${origin}/auth/callback?next=/`,
    queryParams: { scope: "profile_nickname,profile_image" },
  },
});
```

5. `/auth/callback`에서 PKCE code exchange → 앱 세션 브릿지  
6. 프로필 정규화에서 email 없을 때 `{id}@users.kakao.id`  
7. retired/test project ref 하드코딩 금지 + env 검증으로 차단  
8. `NEXT_PUBLIC_*` 변경 시 반드시 프로덕션 재배포

### 4.3 절대 하지 말 것

| 금지 | 이유 |
|------|------|
| Kakao Redirect에 사이트 `/auth/callback`만 등록 | KOE006 — GoTrue는 Supabase 호스트를 보냄 |
| `custom:kakao`와 built-in `kakao` 혼용 | provider id / userinfo 불일치 |
| Vercel에 빈/예시 `NEXT_PUBLIC_SUPABASE_URL` | 잘못된 redirect_uri 또는 설정 실패 |
| 테스트·본체 프로젝트 키 교차 | 콜백·유저 DB·세션 완전 붕괴 |
| REST Key를 클라이언트에 노출하며 직접 token 교환 | Secret 유출 · 아키텍처 이탈 |
| 로그인 Key와 JS 공유 Key 혼동 | 서로 다른 카카오 제품 |

### 4.5 검증 시나리오

1. 시크릿 창에서 「카카오로 계속하기」  
2. authorize URL의 `redirect_uri`가 canonical Supabase callback인지 확인  
3. 동의(닉네임/프로필만) 후 `/auth/callback` → `/auth/bridge` → `/` (또는 terms)  
4. Network/Application에서 `sb-oorujqb…-auth-token`만 존재, retired ref 키 없음  
5. 이메일 없는 계정으로도 bridge `ok: true`  
6. KOE006 재현 테스트: 잘못된 URL을 Kakao에만 넣고 → 실패하는지로 역검증
