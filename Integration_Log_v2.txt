## 0. 한 줄 요약 (현재 아키텍처)

| 항목 | 실제 구현 |
|------|-----------|
| 공유 방식 | **Kakao JavaScript SDK v2** — `Kakao.Share.sendDefault` (피드 템플릿) |
| 이미지 | `Kakao.Share.uploadImage`로 파일 업로드 → CDN URL 사용 (실패 시 사이트 고정 이미지 폴백) |
| SDK 로드 | **온디맨드** (`lib/kakaoShare.ts`). `app/layout.tsx`에서 전역 로드/init **하지 않음** |
| JavaScript 키 | **하드코딩** (청크 join). `Kakao.init`은 env를 읽지 않음 |
| 올바른 JS 키 | `11b99bf50fa43f53e8fab8e5272ff2b4` (중간 `50fa` — `50af` 오타 금지) |
| 차단된 레거시 키 | `1100b60f0a48158bf8afb868272112b4` |
| 로그인(OAuth) | **별도** — Supabase Kakao Provider (REST API 키 + Client Secret). Share JS SDK와 키/생명주기 분리 |
| 대표 오류 | **4011** (앱키/도메인/init 충돌), 콘솔 **-401** 계열과 함께 관측됨 |

카카오 **로그인**과 카카오 **톡 공유**는 같은 “카카오 앱”을 쓰더라도 **키 종류·SDK·초기화 경로가 다릅니다.** 혼동하면 4011이 재발합니다.

### 1.4 `lib/kakaoShare.ts` 내부 로직 구조

```
shareImageViaKakao({ file, title, description, ... })
        │
        ├─ (optional) uploadImageToKakao(file)
        │       └─ ensureKakaoReady() → Kakao.Share.uploadImage
        │
        └─ sendKakaoFeedShare({ title, description, imageUrl })
                └─ ensureKakaoReady()
                        ├─ loadKakaoScript()   // CDN 2.8.2, 1회 캐시
                        ├─ resolveInitKey()   // sanitize + length 32 + legacy block
                        ├─ reuse OR cleanup+init (마커 불일치 시에만 cleanup)
                        └─ Kakao.Share.sendDefault(feed payload)
```

**세션 재사용 규칙 (`ensureKakaoReady`):**

1. 이미 `Kakao.isInitialized()` 이고 `window.__SCA_KAKAO_APP_KEY ===` 현재 JS 키 → **init 재호출 없이 reuse**
2. 초기화됐지만 마커가 없거나 **다른/레거시 키** → `Kakao.cleanup()` 1회 후 올바른 키로 `init`
3. **매 클릭마다 cleanup+init 하지 않음** (과거 4011 유발 패턴)

마커: `window.__SCA_KAKAO_APP_KEY`

## 2. 트러블슈팅 및 에러 해결

### 2.1 Error Code **4011** / **-401** — 앱 키·공백·오타

#### 증상

- 공유 클릭 시 카카오 SDK 오류 **4011** (invalid app key / 미등록 도메인 / 잘못된 init 등)
- 개발자 도구·카카오 응답에서 **-401** 계열과 함께 관측되는 경우 있음
- 콘솔에 **레거시/오타 키** prefix가 보이거나, env·캐시와 코드가 불일치

#### 원인 A — JavaScript 키 글자 오타 (`50fa` vs `50af`)

| 구분 | 값 |
|------|-----|
| **정답 (현재 코드)** | `11b99bf5` + `0fa43f53` + `e8fab8e5` + `272ff2b4` → `11b99bf50fa43f53e8fab8e5272ff2b4` |
| **잘못된 오타 예** | 중간을 `50af`로 적는 경우 (`…bf50af43…`) — 카카오 콘솔 JS 키와 불일치 → 4011 |
| **레거시(차단)** | `1100b60f0a48158bf8afb868272112b4` — 옛 빌드/캐시에 남아 있으면 오동작 |

코드는 키를 **문자열 한 덩어리로 붙여넣지 않고 청크로 join**하여 공백·개행이 끼어들기 어렵게 함:

```js
export const KAKAO_JS_KEY = ["11b99bf5", "0fa43f53", "e8fab8e5", "272ff2b4"].join("");
```

#### 원인 B — 숨은 공백(Whitespace)

복붙 시 스페이스, NBSP(`\u00A0`), zero-width, BOM이 키에 섞이면:

- 길이가 32가 아니게 되거나
- 콘솔 키와 바이트 단위로 달라져 **4011**

대응: `sanitizeKakaoJsKey()`로 **모든 공백류 제거** 후 length/일치 검증.

```js
function sanitizeKakaoJsKey(raw: string): string {
  return String(raw ?? "").replace(/[\s\u00A0\u200B\uFEFF]+/g, "");
}
```

#### 원인 C — 잘못된 키 종류 사용

| 키 종류 | 용도 | Share `Kakao.init`에 사용? |
|---------|------|------------------------------|
| **JavaScript 키** | JS SDK Share | **예 (필수)** |
| REST API 키 | 서버/로그인(Supabase Client ID) | **아니오** |
| Native 앱 키 | iOS/Android 앱 | **아니오** |
| Client Secret | OAuth 비밀 | **절대 브라우저에 노출 금지** |

REST 키로 `Kakao.init` 하면 4011/인증 실패가 납니다.

#### 원인 D — 도메인 미등록

4011 회피를 위해 **양쪽**에 동일 웹 도메인 등록:

1. [앱] → [플랫폼 키] → [JavaScript 키] → **JavaScript SDK 도메인**
2. [앱] → [제품 링크 관리] → **웹 도메인**

등록 예:

- `https://www.studio-canvas-ai.com`
- `https://studio-canvas-ai.com`

#### 해결 요약

1. 콘솔 JS 키와 코드 키를 **문자 단위로** 대조 (`50fa` 확인)
2. env에 의존하지 않고 `lib/kakaoShare.ts` 하드코딩만 `init`
3. 레거시 키 Set으로 차단
4. sanitize + length === 32 검증
5. 도메인 이중 등록
6. 전역 layout init 제거 → 잘못된 키가 HTML에 박히는 경로 차단

### 2.2 클릭마다 `cleanup` + 중복 `init` 충돌

#### 증상

- 첫 공유는 되거나, 반복 클릭 시 4011 / 간헐 실패
- SDK가 “이미 초기화됨” / 세션 꼬임

#### 원인

과거 패턴: **공유 버튼마다** `Kakao.cleanup()` 후 다시 `Kakao.init(key)`.

- cleanup이 내부 상태를 비운 직후 즉시 재init하면 레이스·중복 init
- layout 전역 init + 클릭 시 재init이 **이중 채널**로 충돌

#### 해결 (세션 재사용)

`ensureKakaoReady()`:

```
if (!initialized || markerMismatch)
  → (mismatch면 cleanup 1회) → init(currentKey) → 마커 저장
else
  → reuse (init 호출 없음)
```

- **정상 세션**: 재사용
- **스태일/레거시 마커**: cleanup은 **그때만**

레이아웃에서 전역 SDK 스크립트·layout-init·4011 진단 스크립트 **제거**.

---

### 2.3 브라우저 기본값 (Edge vs Chrome) · 세션 엇갈림

#### 증상

- Chrome에서는 되고 Edge(또는 그 반대)에서는 4011 / 옛 키
- 콘솔에 레거시 키(`1100…`)가 보이는데 저장소 코드에는 없음

#### 원인

| 요인 | 설명 |
|------|------|
| 브라우저별 캐시 | Service Worker / HTTP 캐시에 **옛 layout + 옛 JS 키** HTML/번들 잔존 |
| 기본 브라우저 전환 | Windows “기본 앱”이 Edge↔Chrome이면 **쿠키·로컬스토리지·캐시가 완전히 다른 프로필** |
| 전역 init 잔재 | 옛 배포가 `document`에 Kakao를 심어 둔 탭을 오래 열어 둔 경우 |

#### 대응

1. 전역 layout Kakao 제거 → 새 배포 후 **하드 리프레시** (Ctrl+Shift+R) 또는 캐시 비우기
2. `__SCA_KAKAO_APP_KEY`로 탭 단위 키 추적; 불일치 시 cleanup+재init
3. `BLOCKED_LEGACY_KAKAO_JS_KEYS`로 옛 키 재사용 방지
4. 디버그: `localStorage.sca_kakao_debug=1` 또는 `NEXT_PUBLIC_KAKAO_DEBUG=true` → `[kakaoShare]` 로그
5. Edge/Chrome **각각**에서 시크릿 창으로 재검증 (프로필 격리 확인)

## 3. 카카오 개발자 콘솔 및 SDK 연동

### 3.1 키 종류와 관리

| 키 | 콘솔 위치 | Studio Canvas 사용처 |
|----|-----------|----------------------|
| **JavaScript 키** | 앱 → 앱 키 | `lib/kakaoShare.ts` → `Kakao.init` (Share only) |
| **REST API 키** | 앱 → 앱 키 | Supabase Auth → Kakao Provider Client ID (로그인) |
| **Client Secret** | 앱 → 보안 | Supabase / 서버만 (브라우저 금지) |
| **네이티브 앱 키** | 플랫폼 | 본 웹 앱 Share 경로에서 미사용 |

문서화된 정답 JS 키 (`.env.example` / 코드 동일):

```text
11b99bf50fa43f53e8fab8e5272ff2b4
```

`NEXT_PUBLIC_KAKAO_JS_KEY`는 **문서·동기화용**일 뿐, 런타임 `Kakao.init`은 **하드코딩만** 사용.

### 3.2 SDK 연동 프로세스

| 단계 | 내용 |
|------|------|
| 1. 스크립트 | `https://t1.kakaocdn.net/kakao_js_sdk/2.8.2/kakao.min.js` (async, on demand) |
| 2. 준비 | `ensureKakaoReady()` — sanitize → (필요 시 cleanup) → `Kakao.init(jsKey)` |
| 3. 이미지 | (선택) `Kakao.Share.uploadImage({ file })` ≤ 5MB |
| 4. 공유 | `Kakao.Share.sendDefault({ objectType: "feed", content, buttons, installTalk: true })` |
| 5. 링크 | `mobileWebUrl` / `webUrl` = `https://www.studio-canvas-ai.com` |

### 3.3 `Kakao.init()` 생명주기

```
[페이지 로드]
  └─ layout: Kakao 없음

[첫 카카오 공유 클릭]
  └─ loadKakaoScript (1회 Promise 캐시)
  └─ init(JS_KEY) + __SCA_KAKAO_APP_KEY = JS_KEY

[이후 공유 클릭]
  └─ isInitialized && marker OK → reuse (init 없음)

[마커 불일치 / 레거시]
  └─ cleanup() → init(올바른 키) → 마커 갱신
```

로그인 OAuth는 Supabase 리다이렉트 플로우이며 **이 init 경로를 공유하지 않음**.

### 3.4 로그인용 Redirect (참고)


Share JS SDK 도메인 설정과는 **별도 체크리스트**.

## 8. FAQ

**Q. env의 `NEXT_PUBLIC_KAKAO_JS_KEY`를 바꿔도 공유 키가 안 바뀌나요?**  
A. 맞습니다. 런타임 `Kakao.init`은 `lib/kakaoShare.ts` 하드코딩만 사용합니다. 키 변경 시 **그 파일을 수정**하고 배포하세요.

**Q. 4011이 다시 나오면?**  
A. (1) 키 문자 대조 `50fa` (2) 도메인 이중 등록 (3) 하드 리프레시/다른 브라우저 캐시 (4) cleanup을 매 클릭에 넣지 않았는지 (5) REST 키로 init 하지 않았는지.

**Q. 카카오 로그인 실패와 공유 4011은 같나요?**  
A. 아닙니다. 로그인은 REST+Redirect(Supabase), 공유는 JS 키+SDK입니다. 각각 콘솔 설정을 확인하세요.
